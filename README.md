# 日本株デイクローズ・リサーチツール（デモ検証フェーズ）

後場終了後に日経225構成銘柄の値動き・出来高・決算前後の過去パターンを分析し、
根拠付きスコアリング形式でTOP5候補と参考指値をまとめたレポートを生成するツール。

**注意: 「勝率」を保証するものではありません。** 断定的な勝率表示は行わず、
スコアと根拠を提示するだけの分析支援ツールです。実発注機能はなく、
数週間はデモ（ペーパートレード）検証フェーズとして、予測と翌日実結果を
突き合わせて的中率を記録・確認しながら運用します。

## セットアップ

```bash
pip install -r requirements.txt
```

## 実行方法

```bash
python run_daily.py
```

過去日を指定して実行する場合:

```bash
python run_daily.py --date 2026-08-20
```

## 自動実行（Windowsタスクスケジューラ）

平日の後場終了後（15:35以降）に自動実行する設定手順。

1. `Win+R` → `taskschd.msc` でタスクスケジューラを開く
2. 右側「基本タスクの作成」をクリック
3. 名前: `日本株デイクローズリサーチ`（任意）
4. トリガー: 「毎週」を選択 → 月・火・水・木・金にチェック → 開始時刻 `15:35`
5. 操作: 「プログラムの開始」を選択
   - プログラム/スクリプト: `C:\Users\genepa\Documents\jp-stock-research\run_daily.bat`
   - 開始（オプション）: `C:\Users\genepa\Documents\jp-stock-research`
6. 完了後、タスクのプロパティを開き「全般」タブで「ユーザーがログオンしているかどうかにかかわらず実行する」を選ぶと、PC起動中であれば未ログイン状態でも実行される
7. 動作確認: タスク一覧から右クリック→「実行」で手動実行し、`reports/`配下にその日の日付のレポートが生成されることを確認する

**注意**: 日本の祝日（市場休場日）はスケジューラ側では判定していない。休場日に実行された場合、対象銘柄の当日データが取得できず「候補なし」のレポートになる想定（システムとしてはエラーにはならない）。

### 2026-11-09: 前営業日の結果を、各側（買い/売り）の先頭に表示

- 本日の予想を見る前に、前営業日の予想がどうなったかを確認できるようにした（サイトの各側の先頭）。
  スコアボード（的中・不的中・不成立・未確定の件数）と、順位ごとの結果（指値・始値→終値・リターン・成行の結果）を出す。
- 状態: 未評価=未確定 / 約定なし=不成立 / 約定かつリターン>0=的中 / それ以外=不的中。
  不成立でも、成行（寄り→引け）で入った場合の結果は併記する。
- レポートMDには「## 前営業日の結果（買い/売り）」として出力（`tracking/previous.py`）。

### 2026-11-09: 寄り前情報（ギャップ/ATR・想定値幅・前日出来高・地合い・日足位置）の検証

- `python run_preopen_study.py`（先に `run_backtest.py` でキャッシュを作る）。前日までの確定値と想定始値
  （実際の始値で代用）から、「始値で入り同日の終値で決済」した結果を、事前に決めた50通りのルールで比較する。
- 偶然との区別: 日単位のブートストラップ（既定20,000回）で、基準（同じ向きの全件）との差の95%区間とp値を出す。
  採用候補（◎）は、前半で多重比較補正後p<0.05/48、後半でp<0.05、両期間で費用(往復0.1%)後プラス、の全てを満たすものだけ。
- 結果（2024-06〜2026-11、130,356件）: 採用候補なし。PTS・ADR・寄り前気配・適時開示・SNSは無料データで取得できず未検証。
- 費用を引いたバックテストは `python run_backtest.py --cost`（結果は `data/backtest_cost.md`）。

### 2026-11-09: 約定方法の比較バックテスト（指値 / 成行 / 持ち越し / 利確・損切り）

- `python run_backtest.py --execution` で、同じスコアの候補を、約定方法だけ変えて比較する（結果は `data/backtest_execution.md`）。
  - 指値: 0% / 0.25% / 0.5%（現行）/ 1.0%
  - 成行: 寄り付きで入って引けで決済（open→close）、2日後・3日後の引けで決済
  - 成行＋利確/損切り: (+1%/-1%)・(+2%/-1%)・(+1.5%/-1.5%)・(+2%/-2%)。同じ日に両方に届いた場合は損切りを先に付ける（保守的）
  - 引け→引け（参考・実行はできない理論値）
- 選び方は、top（スコア上位5件）/ reversal（逆張り上位5件）/ all（全候補の平均＝比較用の基準）。
  allと比べて、スコアで選んだ効果があるかを見る。
- 前半70%・後半30%に分け、両方でプラスの条件に ◎。偶然を含み得るため、デモ期間での追跡が必要。

### 2026-11-09: 不的中の原因記録と「次回への示唆」

- 答え合わせで「約定したが的中しなかった」予測に、原因タグ（地合い悪化/上昇、寄りで下落/上昇、
  急騰後の反動/急落後の反発、その他、データ不足）を自動で付けて `predictions.miss_causes` に記録する。
  判定の定義としきい値は `analysis/miss_analysis.py` の冒頭に記載（複数タグが付くことがある）。
- サイトの成績の下に「不的中の履歴」ボタンを追加。タグ別の件数と、件数に基づく定型の
  「次回への示唆」（断定しない・スコアは自動では変えない）、各予測の詳細（日経平均・寄り付きの値）を表示する。
- **記録は、この変更を取り込んだ後に登録した予測から**（予測時の終値・騰落率・出来高倍率・翌日の始値・
  日経平均の前日比を新たにDBへ保存するため）。それ以前の予測は履歴に出ない。
- 示唆を受けてスコアを変える場合は、`run_backtest.py` で確かめてから別途判断する。

### 2026-11-06: バックテスト（地合い・過熱度フィルターの検証）

- `python run_backtest.py` で、日経225の過去約900日分を使い、買い・売りTOP5を毎営業日選んで
  翌営業日の値動きで答え合わせする（本番と同じ約定ルール）。結果は `data/backtest_result.md`。
- 検証する条件: 地合い（日経平均が25日移動平均の上/下）、過熱度（25日移動平均乖離率・RSI14）。
  期間の前半70%と後半30%に分けて、両方で改善した条件だけを候補とみなす。
- 本番のスコアリングは変更していない。取り込むかどうかは結果を見てから別途判断する。
- 初回は株価と決算日の取得に数分かかる（`data/backtest_cache.json` にキャッシュ）。
  `--no-earnings` で決算日の取得を省略できる。手数料・スリッページは含まない。

## プロジェクト構成

- `data_sources/` - 株価・決算データ取得（デフォルト: yfinance）
- `analysis/` - テクニカル・決算パターン分析、スコアリングロジック
- `tracking/` - 予測記録・翌日結果との答え合わせ（SQLite）
- `report/` - Markdownレポート生成
- `run_daily.py` - エントリーポイント
